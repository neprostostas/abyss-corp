## Як це працює

Netlify віддає статичну гру. Supabase Auth перевіряє пароль, надсилає підтвердження пошти та посилання відновлення; PostgreSQL зберігає ігровий прогрес за ID акаунта. Паролі не потрапляють у таблицю прогресу або код гри.

Прогрес автоматично записується в браузері кожні 2 секунди та синхронізується з базою кожні 15 секунд. У налаштуваннях є **Save now**. Після входу на іншому пристрої гра завантажує прогрес акаунта. Якщо два пристрої змінили його паралельно, гра автоматично бере актуальну хмарну копію, а локальну архівує. Валюти не об’єднуються, вікна вибору більше немає.

Запит на збереження має власний ID. Якщо сервер зберіг прогрес, але вкладка закрилася до відповіді, повторний запит визнає попередній запис, а не створює зайвий конфлікт. Локальний журнал також зберігає зміни, які ще не встигли піти в хмару.

Для початкового завантаження акаунта потрібен інтернет. Уже завантажена гра працює під час тимчасової втрати зв'язку та відновлює синхронізацію при поверненні мережі. Не очищуйте сховище браузера, доки є несинхронізований прогрес.

Старе браузерне збереження не видалене. В **Settings → Import previous device progress** можна явно перенести його в поточний акаунт. Перед заміною створюється резервна копія. Інший акаунт не отримує цей прогрес автоматично.

## Перегляд бази

- У грі: `/database`. Доступ лише адміністраторам, режим читання. Вкладки Profiles, Accounts, Saves, Progress, Admins та Invitations показують усі дані гри, статуси Auth і права доступу. Є пошук, пагінація й перегляд повного JSON запису. Паролі й токени не виводяться.
- Повний [Table Editor Supabase](https://supabase.com/dashboard/project/qduhqhhhsboljuipruvy/editor).
- [Користувачі Supabase Auth](https://supabase.com/dashboard/project/qduhqhhhsboljuipruvy/auth/users).

Першим адміністратором призначено `neprostostas.gg@gmail.com`; акаунт уже створено, email підтверджено та доступ активний. Це окремий ігровий акаунт; вхід у панель Supabase не створює його. Після підтвердження в Settings з'явиться посилання **Database**.

Щоб надати доступ іншому вже підтвердженому користувачу, оператор може виконати в SQL Editor:

```sql
insert into private.admin_users(user_id)
select id from auth.users
where lower(email) = 'admin@example.com' and email_confirmed_at is not null
on conflict do nothing;
```

Звичайний гравець не може читати чужі записи навіть напряму через API. Адмінський перегляд не показує паролі чи токени.

## Конфігурація збірки

`netlify.toml` містить Node 24, команду збірки, папку `dist`, SPA rewrite та публічні параметри цього Supabase-проєкту. Publishable key можна включати у фронтенд: доступ до даних обмежують політики PostgreSQL. **Secret/service-role key чи пароль SMTP у VITE-змінні додавати не можна.**

Локальне `.env.local` уже налаштоване й виключене з Git. Для іншого середовища скопіюйте `.env.example` та вкажіть URL/publishable key потрібного проєкту. Після зміни Vite-змінних потрібна нова збірка.

`/reset-password` та `/database` обслуговуються через SPA rewrite, тому пряме відкриття й refresh працюють на Netlify. При зміні домену також оновіть [Auth → URL Configuration](https://supabase.com/dashboard/project/qduhqhhhsboljuipruvy/auth/url-configuration).

## Листи

Для публічної реєстрації потрібен custom SMTP: [вбудована пошта Supabase](https://supabase.com/docs/guides/auth/auth-smtp) обмежена учасниками організації та невеликою кількістю листів.

Для цього проєкту вже підключено **Brevo Free**: [до 300 листів на день](https://help.brevo.com/hc/en-us/articles/208589409-About-Brevo-s-pricing-plans). Ліміт Auth у Supabase - 30 листів на годину, інтервал повторного листа - 60 секунд. Ключ SMTP зберігається тільки в налаштуваннях Supabase; він не потрібен Netlify, браузеру чи GitHub.

Налаштування підключення: `smtp-relay.brevo.com`, порт `587`, username з розділу **Brevo → SMTP & API**, password - окремий SMTP key, ім'я відправника **Abyss Corp**. Не використовуйте пароль від акаунта Brevo замість SMTP key. Адреса відправника `neprostostas.gg@gmail.com` підтверджена в Brevo, ім’я відправника - Abyss Corp. Отримання листа реєстрації підтверджено власником.

SMTP-ключ **Abyss Corp Supabase Auth** створено зі строком дії до 26.10.2027. Brevo також деактивує ключі після 90 днів без надсилань. Перед закінченням строку створіть новий SMTP key і замініть пароль у Supabase → Auth → Emails → SMTP Settings. IP-фільтр для SMTP вимкнений, щоб керована інфраструктура Supabase могла надсилати листи; доступ захищений окремим ключем і TLS. Налаштування 2FA акаунта Brevo не змінювалися.

Поки немає власного домену, Brevo може [замінювати Gmail-відправника на свій технічний домен](https://help.brevo.com/hc/en-us/articles/14925263522578-Comply-with-Gmail-Yahoo-and-Microsoft-s-requirements-for-email-senders). Для власної адреси бренду та стабільнішої доставлюваності надалі потрібен власний домен із DKIM/DMARC. Netlify-піддомен не надає керування DNS домену `netlify.app`.

## Перевірка

```sh
npm ci
npm run check
npm run build
npm run dev
```

`check` перевіряє TypeScript, ESLint і форматування. Старі тестові файли та Vitest видалено; тести під час деплою не запускаються.

Основний сценарій: створити акаунт → підтвердити email → увійти → запустити виробництво → Save now → оновити сторінку → перевірити прогрес → вийти → відновити пароль через лист. Для адміністратора додатково відкрити `/database`; для звичайного акаунта доступ має бути заборонений.

## Лідерборд і межі безпеки

Кнопка **Leaders** відкриває рейтинг, ваше місце та зміну ніку. Email не публікується. Порядок: глибина → покращення → дослідження → автоматизація → кредити. Значення оновлюються зі збереженого прогресу, а не з окремо надісланого клієнтом числа рейтингу.

Водночас симуляція ще клієнтська: досвідчений гравець може змінити свій валідний save. RLS захищає чужі акаунти, але не перетворює локальну економіку на серверний античіт. Тому це дошка прогресу без змагальних нагород; для чесних призових рейтингів наступним кроком потрібна серверна обробка ігрових команд.

## Чому прибрано localhost

`localhost` та `127.0.0.1` завжди означають пристрій того, хто відкриває посилання, а не ваш комп'ютер у мережі. Вони звичайні для локальної розробки, але не потрібні у списку повернень публічного проєкту. Зараз залишені лише чотири точні HTTPS-адреси основного сайту та preview.

Цей список не забороняє запускати змінений frontend локально: publishable key публічний за призначенням. Доступ до бази визначає підписаний токен акаунта й PostgreSQL RLS, а не адреса frontend. Інший гравець не може змінити налаштування Supabase, читати ваш приватний save чи призначити себе адміном через свій локальний код.

При локальній розробці вхід із паролем працює. Листи підтвердження й відновлення повертають на контрольований account-preview, а не localhost. Документація: [Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

## Очищення проєкту

Старі шрифти, невикористані модальні стилі, дубльовані нотатки та кеш CLI прибрані. Непотрібний SQLite-архів видалено після переходу на Supabase. Робочий браузерний save, акаунтні журнали й міграції не видалялись. Нові Oxanium і Manrope зберігаються локально з їхніми OFL-ліцензіями.

Перевірка витоків паролів у Supabase доступна лише на платному Pro-плані та не вмикалась: [опис функції](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). Обов’язкове підтвердження email і мінімум 10 символів залишаються активними.

## Аналітика

Відвідування вимірює PostHog EU. Cookie-банер пропонує рівноцінні **Essential only** / **Allow analytics**; вибір можна змінити в Settings → Cookies або `/privacy`. Без згоди події та аналітичні cookies не створюються. Сторінки адміністратора й відновлення пароля не відправляються в аналітику.

`/analytics` доступна тільки адміністратору: унікальні відвідувачі, перегляди, візити й графік за 7/30/90 днів. Звіти відображають тільки production та користувачів, які погодились на аналітику. Дати - UTC. Ключ читання PostHog зберігається в Netlify environment у приватному environment сайту, не у VITE-змінних або репозиторії.

Змінні: `VITE_POSTHOG_KEY` - публічний токен проєкту для збірки; `POSTHOG_PROJECT_ID` і `POSTHOG_READ_KEY` - приватні серверні змінні. Функція також використовує `SUPABASE_URL` і `SUPABASE_PUBLISHABLE_KEY`, а права перевіряє через JWT користувача та `is_database_admin()` без service-role ключа.

PostHog Free дає 1M подій/місяць без платіжної картки. Повні умови: https://posthog.com/pricing. Не називайте ці лічильники абсолютною кількістю всіх відвідувачів: відмови, блокувальники й обмеження браузера зменшують виміряну кількість.

PostHog EU: проєкт **Abyss Corp**, ID `321898`. Серверний ключ обмежений `query:read` тільки цього проєкту; session replay вимкнений. Аналітичні cookie `abyss_visitor` (180 днів) і `abyss_visit` (30 хвилин) існують тільки після згоди; відмова видаляє їх.

Безплатний Netlify не дозволяє розділяти scopes змінних: вони доступні build та server runtime. `POSTHOG_READ_KEY` не має VITE-префікса й не імпортується клієнтським кодом; тільки Netlify Function читає його через `process.env`. Доступ до значень у налаштуваннях має лише команда Netlify.

Локальні звіти аналітики використовують Vite-проксі до production Netlify Function: потрібен інтернет і вхід адміністратора, приватний PostHog-ключ локально не потрібен. Міграція `20261027000100_admin_overview.sql` додає лише захищений read-only огляд. `20261027000200_expedition_saves.sql` дозволяє збереження v6 і v7; її потрібно застосувати до публікації нового клієнта. Нових таблиць немає. Після оновлення до save v7 відкриті старі вкладки гри слід оновити.
